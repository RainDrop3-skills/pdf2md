# `--everytime`: 에타 기출 ↔ 페이지 매핑

에브리타임(에타) 강의평/시험정보 게시판에 올라온 기출 후기를 강의 PDF 페이지와 연결한다. 학생이 노트를 읽다가 "이 페이지는 실제로 시험에 나왔던 곳"임을 바로 알게 하는 것이 목적이다.

## 1. 파일 찾기

PDF가 있는 디렉토리 기준(하위 폴더 한 단계까지)에서 다음을 찾는다.
- 파일명에 `에타`, `에브리타임`, `everytime`, `eta`(대소문자 무시, 단어로 쓰인 경우)가 들어간 것
- 확장자: `.png`, `.jpg`, `.jpeg`, `.md`
- 제외: `*-페이지별-설명.md` (이 스킬의 산출물)

찾은 게 없으면 사용자에게 알리고, 에타 표시 없이 일반 노트로 진행할지 묻는다.

## 2. 문제 목록 만들기

### 매핑 md가 이미 있을 때 (예: `소웨공-에타-강의매핑.md`)
- 그 파일이 **문제 번호의 기준**이다. 이미 만든 다른 장 노트들과 번호가 같아야 학생이 헷갈리지 않는다.
- 매핑 md에 이 PDF의 페이지가 이미 적혀 있으면 출발점으로 쓰되, 페이지를 실제로 분석하면서 맞는지 검증한다. 더 적절한 페이지를 찾으면 노트에 반영하고 마무리 보고에서 알려 준다.
- 매핑 md에 없는 이미지가 있으면(새로 추가된 캡처) 그 문제는 기존 마지막 번호 다음부터 이어서 번호를 매긴다.
- 매핑 md 파일 자체는 사용자가 요청하지 않으면 수정하지 않는다. 바꿀 점이 있으면 보고에서 제안만 한다.

### 이미지 캡처만 있을 때
- 이미지를 파일명 순서대로 직접 보고 문제를 옮겨 적는다. 캡처끼리 겹치는 부분(같은 게시글이 두 장에 걸침)은 하나로 합친다.
- 문제 하나하나에 Q1, Q2 ... 번호를 붙인다. 문제 형식이 불분명한 후기("UML 많이 나옴")도 시험 범위 힌트로 쓸 만하면 번호를 붙인다.
- 별도 매핑 파일은 만들지 않는다. 번호와 문제 요약은 노트 끝 `## 에타 기출 연결` 표가 기준이 된다.

## 3. 페이지에 표시하기

- 문제의 답이나 정의가 **슬라이드에 직접 있거나**, 문제를 푸는 데 **핵심 근거**가 되는 페이지에만 표시한다. 단어 하나 겹친다고 다 달면 표시가 의미를 잃는다.
- 헤딩 끝에 붙인다: `## p.13 Software Size: Militaries 📌 에타 Q17, Q20`
- 그 페이지 본문(보통 설명이나 시험 포인트 근처)에 연결을 한 줄로 남긴다:
  - `- **에타 Q19**: 개발 비용이 주어졌을 때 유지보수 비용 → 이 페이지의 67:33 비율로 **개발 비용 × 2**`
- 슬라이드와 기출 내용이 어긋나면(용어가 바뀜, 버전 차이 등) `[주의]`로 알려 준다. 예: "에타에선 primary actor, 2026 강의 용어는 Timer Actor".
- `## 장 구성` 표의 해당 구간에도 `📌 Qn`을 붙여 두면 좋다.
- `## 읽는 법`에 다음 줄을 넣는다:
  - `- **에타 표시**: 에타 기출과 연결되는 페이지에는 \`📌 에타 Qn\`을 붙임 (번호는 \`<매핑 md 파일명>\` 기준)` — 매핑 md가 없으면 "번호는 이 노트 끝 '에타 기출 연결' 기준"

## 4. 노트 끝 정리 표

```markdown
## 에타 기출 연결

| # | 에타 문제 (요약) | 이 장 페이지 | 근거 | 정답/포인트 |
|---|---|---|---|---|
| Q4 | Performance 지표가 아닌 것 | p.12~15, p.60 (#65) | ● | 시간·자원·용량 지표 |
| Q7 | 악조건에서도 성능 유지 | p.93, p.96 | ● | 강건성 (Robustness) |

- 근거: ● 슬라이드에 답이 그대로 있음 / ◐ 관련 개념만 있고 추론 필요
- 이 장과 관련 없는 문제: Q1, Q2, Q3 ... (다른 장 또는 범위 밖)
```

관련 없는 문제를 따로 적어 두면, 학생이 "이 문제는 다른 장에서 찾아야 한다"는 것을 알 수 있다.
